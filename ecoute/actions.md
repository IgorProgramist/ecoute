COOKBOOK - UNITY CANVAS (uGUI). Detailed knowledge for follow-up questions like "tell me more", "how exactly do you set it up", "what are the steps".
Each topic below has a SUMMARY, the LESSON (the cleaned Unity lesson text), STEPS, and WATCH OUT where there is something to add.


COMMON RULES FOR ALL UI ELEMENTS (Canvas, Interactable, Navigation, events):
- Every UI element must be a child of a Canvas, directly or deeper. If a pre-made element is created and no Canvas exists, Unity creates a Canvas.
- An EventSystem is added to the scene when the Canvas is created. It detects clicks, drags and navigation and calls the events of the elements.
- Interactable decides whether an element accepts input. With Interactable off the element shows the Disabled state.
- Navigation describes how elements are selected with keyboard or controller. In most cases it stays on Automatic.
- Buttons, Sliders, Scrollbars and Toggles share the same Transition property - see UI TRANSITIONS.
- On Click and On Value Changed are function lists in the Inspector. A row has an object field, a function menu and a parameter field. To receive the live value, pick the function from the Dynamic part at the top of the menu and leave the parameter field empty.


UI TRANSITIONS (states of Button, Slider, Toggle - Normal, Pressed, Disabled):
SUMMARY
- How a Button, Slider, Toggle or Scrollbar looks in the Normal, Highlighted, Pressed and Disabled states.
- Four modes - None, Color Tint (default), Sprite Swap, Animation.
LESSON
The transition property defines how a UI element behaves in each state and how it behaves when changing states. The lesson uses the Button as the example, but transitions work the same for each UI element with transitions.
By default the Button displays the Normal state. Depending on the transition mode, a Button can also display a Highlighted, Pressed and Disabled state. The transition mode decides whether the Button shows these extra states, and controls the look in each state and the style of the transition between them.
The Highlighted state is set when the pointer hovers over the Button, or the Button is selected with keyboard or controller navigation. The Pressed state is when the Button is held down - pressed but not released. The Disabled state is set when the Button is not interactable.
The transition mode is set with the Transition popup menu.
None has no additional states and no transitions. The Button works as expected, but there is no visual feedback and the unaltered Normal state is displayed at all times.
Color Tint is the default mode. The same graphic is used for each state. Target Graphic is the Image component to be tinted. Normal, Highlighted, Pressed and Disabled Color define the tint applied to the Target Graphic in each state. Color Multiplier multiplies the tint color for each transition by its value; this allows colors greater than one, which is useful for brightening the colors or alpha of graphics whose base color is less than white or less than full alpha. Fade Duration is the time in seconds the transition takes between states.
Sprite Swap uses different sprite images for each state and swaps them depending on the state of the Button. A new graphic is required for each state. Target Graphic is the image for the Normal state. The Highlighted, Pressed and Disabled Sprites are references to the sprites displayed for each state.
Animation allows each transition to be fully animated with Unity's animation system. It is the most powerful mode because of the number of properties that can be animated simultaneously. To use it, an Animator component must be attached to the Button. To add the Animator automatically and generate an Animator Controller with the states already set up, click Auto Generate Animation. The new Animator Controller must be saved. Nothing else has to be done with it; the transitions between states can be customized, but this is not necessary. Unlike most Animator Controllers, this controller also stores the animation clips for the Button's transitions.
With the controller attached and the Button selected, the animation for each state is edited in the Animation window (Window, Animation, or Ctrl+6 on Windows, Cmd+6 on Mac). Use the animation clip popup menu to select the clip. The pre-made controller has a state for Normal, Highlighted, Pressed and Disabled. In most cases Normal is left empty, with no keyframes, because the Normal look is set by the values on the Button itself. On the other states the most common setup is a single keyframe at 0 seconds. The animation between states is handled by the Animator Controller as it blends between states.
Example - to make the Button wider when highlighted, select Highlighted in the clip popup menu, put the playhead at 0 seconds, press Record, change the width in the Inspector, and leave record mode. In Play mode the Button now grows when highlighted. Any number of properties can be set in this one keyframe.
If several Buttons share the same behavior, they can share one Animator Controller. All of them must have Transition set to Animation and must have an Animator component; then assign the shared Animator Controller to all of them. In Play mode all the Buttons share the same animated transitions.
STEPS
- Color tint on a Button. 1) Select the Button. 2) Check that Transition is Color Tint. 3) Check that Target Graphic points to the main Image. 4) Set Normal, Highlighted, Pressed and Disabled Color. 5) Set Color Multiplier (default 1). 6) Set Fade Duration in seconds.
- Sprite Swap. 1) Select the Button. 2) Change Transition from Color Tint to Sprite Swap. 3) Put the normal sprite in the Target Graphic Image. 4) Assign Highlighted Sprite, Pressed Sprite and Disabled Sprite. 5) Test in Play mode - the sprite changes on hover and press.
- Animated transitions. 1) Select the Button. 2) Set Transition to Animation. 3) Click Auto Generate Animation. 4) Save the generated Animator Controller. 5) Open the Animation window (Ctrl+6). 6) Pick the Highlighted clip. 7) Press Record at time 0. 8) Change the properties in the Inspector, for example size or scale. 9) Stop recording and test in Play mode.
- One Animator Controller for many Buttons. 1) Set up the first animated Button as above. 2) Select the other Buttons. 3) Add an Animator component to each. 4) Set Transition to Animation on all. 5) Assign the same Animator Controller to each Animator.
WATCH OUT
- An Animator on a UI element marks its Canvas as changed every frame while the Animator is enabled, even when nothing visibly changes. On mobile this costs Canvas rebuilds, so for simple button feedback Color Tint or a tween is cheaper than the Animation mode.


UI SLIDER (select a value in a range, also used as health bar or progress bar):
SUMMARY
- Pick a number from a range by dragging a handle - volume, brightness. Also a display only - health bar, progress bar.
- Parts - Background, Fill, Handle. Settings - Direction, Min Value, Max Value, Whole Numbers, Value, On Value Changed.
LESSON
The Slider is a UI element that allows the user to select a numeric value from a predetermined range by dragging the handle. Common controls using a Slider are settings for audio volume, color channels or brightness. The Slider can also be repurposed as a simple display for items like health bars or volume meters.
The Slider's value is set by the position of the handle along the length of the Slider. The value starts at a minimum value and increases up to a maximum value, defining a range between the two.
To create a Slider use the create menu - UI, Slider.
A created Slider is made from a family of GameObjects. The parent GameObject is where the Slider script lives. All the children are the RectTransform and Image components that make up the separate parts of the control - the Background graphic, the Fill graphic which indicates the relative value chosen, and the Handle which is displayed at the location of the chosen value. The Background and Handle are optional.
With transitions on a Slider, any visual change is seen only on the Handle graphic, not on the rest of the element - the Animation transition is the exception.
Fill Rect is a reference to the RectTransform of the graphic used for the filled area; the current value is displayed by the fill graphic. Handle Rect is a reference to the RectTransform of the graphic used for the handle; it is optional and can be None.
Direction sets both the axis and the direction of the value change. The Min value is at the starting end of the direction. With Left To Right, the Min value is at the left, the value increases proportionally as the handle moves to the right, and the Max value is at the right. The choices are Left To Right, Right To Left, Bottom To Top and Top To Bottom.
The range is set by Min Value and Max Value. Min Value can be a negative number, but it should be numerically less than Max Value or aberrant behavior can result.
Whole Numbers clamps the value to whole numbers within the range. If Min and Max are not whole numbers, they are adjusted to the closest whole number when Whole Numbers is selected.
Value is the current value of the Slider. When set in the Inspector at edit time, it sets the starting value.
When the event system detects a click or a drag on the Slider, it calls an On Value Changed event. The Slider has a built-in On Value Changed function list with all the functions called when the value changes. Other events can be detected and used by the Slider, but this requires an additional component.
To hook the current value of the Slider to a component - create a new row in the On Value Changed list, put the GameObject with the desired script into the object field, then in the function menu choose the component and then an eligible function on it. Every time the value changes, On Value Changed is called. To pass the current value, the function must have a float parameter and must be chosen from the Dynamic float part at the top of the list. If the only functions listed are under Static Parameters, the functions have no float parameter and cannot receive the current value. The last field is the parameter field; when the value is passed as a dynamic float it is left blank.
The value of the Slider can also be driven from outside, and the Slider displays the value sent to it. A classic example is a simple health, mana or fuel bar - a script with a reference to the Slider sets its value. In these cases it is best to set Interactable to false, to prevent any input, and to remove the Handle graphic if desired.
STEPS
- Interactive Slider. 1) Right-click in the Hierarchy - UI, Slider. 2) Select the Slider. 3) Set Min Value and Max Value. 4) Turn on Whole Numbers if whole steps are needed. 5) Set Direction. 6) Set the starting Value.
- Send the value to a script. 1) Select the Slider. 2) In On Value Changed press plus. 3) Drag the GameObject with the script into the object field. 4) Open the function menu and pick the script. 5) Pick the function from the Dynamic float part at the top, for example SetAudioVolume. 6) Leave the parameter field empty.
- Health or mana bar from a Slider. 1) Select the Slider. 2) Turn off Interactable. 3) Delete or disable Handle Slide Area. 4) Set Handle Rect to None. 5) In the script keep a reference to the Slider. 6) Set the Slider value from the script when health changes.
WATCH OUT
- Whole Numbers gives steps of 1 only. Other step sizes need a script.


UI SCROLLBAR (handle that gives a normalized value, used with a Scroll Rect):
SUMMARY
- A handle that gives a normalized value - how far along the track it is. Usually connected to a Scroll Rect.
- Settings - Direction, Value, Size, Number Of Steps, On Value Changed.
LESSON
The Scrollbar allows the user to select a normalized value by dragging the handle. Scrollbars are usually used to set or change a value on another UI element or component. They are commonly used with a Scroll Rect, which can hold and mask contents too large to be easily viewed; the Scroll Rect uses the value from the Scrollbar to control how its contents are scrolled.
The Scrollbar's value is set by the position of the handle along the length of the Scrollbar. It is a normalized value that is lowest at one end of the track and highest at the other end.
To create a Scrollbar use the create menu - UI, Scrollbar.
A created Scrollbar is made from a family of GameObjects. The children are the RectTransform and Image components that define the sliding area and the handle graphic. The parent GameObject is where the Scrollbar script lives, and the background Image is a component on the parent.
With transitions on a Scrollbar, visual changes are seen only on the handle graphic, not on the rest of the element - the Animation mode is the exception.
Handle Rect is a reference to the RectTransform of the graphic used for the handle.
Direction sets both the axis and the direction of the value change. With Left To Right, the lowest value is at the left and the value grows as the handle moves to the right. The choices are Left To Right, Right To Left, Bottom To Top and Top To Bottom.
Value is the current value of the Scrollbar; set in the Inspector at edit time, it is the starting value.
Size is the size of the handle as a fraction of the Scrollbar.
Number Of Steps is the number of distinct scroll positions allowed. For smooth continuous scrolling leave it without steps.
When the event system detects a click or a drag on the Scrollbar, it calls an On Value Changed event. The Scrollbar has a built-in On Value Changed function list. Other events need an additional component.
In most cases the Scrollbar is used with a Scroll Rect, which automatically uses the dynamic value of the Scrollbar when they are connected.
STEPS
- Create and tune a Scrollbar. 1) Right-click the Canvas - UI, Scrollbar. 2) Select the Scrollbar. 3) Set Direction, for example Bottom To Top for a vertical one. 4) Set Size so the handle fills a part of the track. 5) Set Number Of Steps - 0 for smooth movement, or a number like 5 for stepped positions.
- Send the value to a script. 1) Select the Scrollbar. 2) In On Value Changed press plus. 3) Put the target GameObject into the object field. 4) In the function menu pick the script and a function under Dynamic float. 5) Leave the parameter field empty.


RECTTRANSFORM AND ANCHORS (position, size, pivot, stretching of UI):
SUMMARY
- RectTransform replaces Transform on UI - a rectangle with width, height and a pivot.
- Anchors pin an element to its parent or make it stretch with the parent. Anchor Presets, Rect Tool, resize versus scale.
LESSON
The RectTransform is the component that replaces the usual Transform on all UI elements. The Transform represents the position, rotation and scale of a 3D object in the scene volume; the RectTransform represents a 2D rectangle specified by a width and a height related to a pivot point. Even though it represents a simple 2D rectangle, the component includes a position along the Z axis as well as rotation and scale, so the element can be manipulated in the scene as a 3D object.
One important difference between a RectTransform and the traditional Transform is the concept of anchors. A RectTransform can be anchored to its parent if that parent also has a RectTransform. Anchoring allows the UI element to move or stretch based on the position and size of the parent's RectTransform. All UI elements must ultimately be the child of a Canvas, even if they are not immediate children. Canvases themselves have a RectTransform, so in almost all circumstances the parent of a UI element also has a RectTransform and the element is anchored to its parent in some way.
In the Scene view it is best to manipulate a UI element with the Rect Tool. It is selected with the Rect Tool button in the toolbar or the shortcut key T. With the Rect Tool it is possible to move, resize and rotate any UI element with one tool. The element is moved by clicking anywhere inside the rectangle and dragging. It is resized by clicking on any edge or corner and dragging; the cursor changes to a double arrow aligned with the resize direction. Holding Shift resizes proportionally. It is rotated by clicking and dragging just outside the rectangle near any corner; the cursor changes to show the tool can rotate.
Resizing or rotating a UI element is done in relation to its pivot point. The pivot point is very much like the center point of a standard GameObject. It is indicated by a blue ring, which by default starts in the center of the element. The pivot can be moved by clicking and dragging the pivot indicator in the Scene view. The pivot does not need to be inside the rectangle; placing it outside can be done for specialized behavior, but this is not common.
Another difference between Transform and RectTransform is the effect of Global and Local space on editing. In Local space the rectangle and handles are aligned with the UI element. In Global space the rectangle and handles are aligned globally and the rectangle shows the bounds of the element. This is most notable when the element is rotated.
In the Scene view anchors are indicated by four small triangles, which by default are grouped together in the center of the parent's RectTransform. This parent can be the Canvas.
In the Inspector the RectTransform is clearly different from the Transform. The position and size of the element are shown in the upper right. Position shows the distance in pixels from the anchor point to the pivot along the X and Y axes. Pos Z is the distance along the local Z axis and is often left at 0. Width and Height are the size of the element in pixels. The position and size fields are dynamic and context sensitive - they depend on the position of the anchors.
RectTransforms can be anchored to their parent if the parent GameObject also has a RectTransform. In most cases every UI element is anchored to its parent in some way. In the Scene view the anchors are four small triangle gizmos. Each triangle is one anchor, and each anchor is associated with one corner of the RectTransform - the upper left anchor with the upper left corner, the lower right anchor with the lower right corner, and so on. Anchors are positioned within the bounds of the parent's rectangle, not the element's rectangle, and cannot be positioned outside the parent's rectangle. Anchors are moved by clicking and dragging a triangle. Clicking in the center of a group of triangles moves them as a group; clicking an individual triangle moves one anchor at a time.
Anchors have a fixed relationship to the RectTransform they are anchoring, and a flexible relationship to the parent's RectTransform they are anchoring to. When an anchor is set, the distance between the anchor and its corner is a fixed value. The anchor's position within the parent's RectTransform, however, is relative to the parent's size. It is a percentage of the parent's size along X and Y, so its absolute position can change when the parent's RectTransform changes. This percentage is a normalized value along each axis, counted from the lower left corner of the parent to the upper right corner.
Practically - if all four anchors are grouped around a single point, the UI element is anchored to that point. If the parent changes size, the anchor moves relative to this change and the element moves along with the anchor. The element does not stretch or resize, because the distance from the anchors to their corners is fixed. If the anchors are separated in any way, the element stretches along with the parent, because the anchors and the space between them are relative to the parent and change in size when the parent changes in size.
How much the element stretches compared to its parent depends on where the anchors are. A few common cases. Anchors at the corners of the UI element - the stretch keeps the element at the same percentage of the parent's area. Anchors at the bounds of the parent - the space between the edge of the element and the bounds of the parent stays the same, which makes a fixed border. A pair of anchors grouped together at the edges of the parent - the element stretches horizontally but not vertically.
The stretching behavior can be tested quickly by grabbing the edge of the parent RectTransform and dragging it. A preview label appears while dragging, and the parent snaps back to its original state when the drag ends. When positioning anchors by hand, holding Shift also changes the element's size.
The way the RectTransform displays position and size changes when the anchors are not grouped together. When all four anchors are grouped, they define a single anchor point, and the RectTransform shows the positional offset from the pivot and the Width and Height. When the anchors are split apart, it shows the fixed values Left, Right, Top and Bottom - the fixed offsets along X and Y from the anchors to their corners. If two anchors are grouped together on one axis, there is no stretching along that axis, and the RectTransform keeps showing position and width, or position and height, for that axis.
For the pivot and anchors there are a number of very common setups. To make these quick the RectTransform has the Anchor Presets window, opened with the Anchor Presets button, which displays the current anchoring choice. The common setups are arranged in a matrix based on the position of the anchors, with fixed anchor points in the middle and the stretch options along the outer edge. The anchors are set by clicking the desired setup. The pivot, the position of the element, or both can be set at the same time by holding Shift and/or Alt while clicking; these keys are noted at the top of the window.
Pivot defines the pivot point of the element with a normalized value along X and Y, counted from the lower left corner to the upper right corner.
Rotation defines the rotation of the element. In the most common cases rotation is only needed along the Z axis, keeping the element in 2D space. Rotation is allowed on all three axes, and the element can be viewed in 3D space.
Before scale, it is important to understand the difference between scaling and size. When adjusting an element's size in the Scene view, or the Width and Height in the Inspector, the element is being resized, not scaled. Resizing changes the RectTransform's width and/or height but does not scale the element. Resizing does not affect font sizes, the border on sliced images, or other items related to the element. When an element is scaled, the entire element is scaled, including fonts and borders. For layout it is generally recommended to resize a UI element rather than scale it. Scaling can be useful for animated effects or other special purposes. A UI element becomes invisible if given a negative size. Negative scaling is supported and can be used for effects, including flipping the element with a scale of -1.
The RectTransform has two optional editing modes. Blueprint mode allows editing RectTransforms as if they were not rotated or scaled; the element cannot be rotated with the Rect Tool in Blueprint mode. Normally, when the pivot or anchor values are edited in the RectTransform, the pivot or anchor moves and the element stays in place, just like in the Scene view. In Raw edit mode the pivot or anchor stays in place and the element moves relative to that fixed item.
Sometimes a RectTransform has some or all of its values driven by a parent RectTransform or another UI component, such as a Layout Group. In these cases some or all of the properties are greyed out and cannot be edited, and a note at the top of the RectTransform says that some values are driven by another component.
STEPS
- Pin an element to a corner. 1) Select the element. 2) Open Anchor Presets. 3) Hold Shift and Alt and click the corner preset - anchors, pivot and position all go to that corner. 4) Set Pos X and Pos Y as the offset from the corner.
- Stretch an element with its parent and keep a fixed border. 1) Select the element. 2) Open Anchor Presets and click the stretch-stretch preset (hold Alt to also fill the parent). 3) Set Left, Right, Top and Bottom to the border size.
- Stretch only horizontally. 1) Pick the horizontal stretch preset at the top, middle or bottom. 2) Set Left and Right, and set Height.
- Test the anchors. Drag an edge of the parent in the Scene view and watch how the child moves or stretches; the parent snaps back when released.


UI BUTTON AND EVENTS (On Click, which functions can be called, parameters):
SUMMARY
- A Button detects a click and calls the functions in its On Click list.
- Which functions can be called, and how parameters are passed.
LESSON
The Button detects user input and can trigger an event. User input is usually the pointer hovering over or clicking on the Button graphic.
To create a pre-made Button use the create menu - UI, Button.
A Button requires an Image script and a Button script. Pre-made Buttons also include a Text element attached as a child. This Text element is optional and can be removed if the Button does not need text.
By default the Button displays the Normal state. The look of the Normal state is set by the Image component attached to the Button. In Color Tint and Sprite Swap the Target Graphic is, in almost all cases, the Image component attached to the Button; the Button script sets this reference automatically if the Image is already on the GameObject when the Button script is added. The states (Normal, Highlighted, Pressed, Disabled) and the transition modes (None, Color Tint, Sprite Swap, Animation) work exactly as described in the UI TRANSITIONS topic.
When the event system detects a press and a release over the same Button, it processes a click and the On Click event is called. The Button has a built-in On Click function list with all the functions called when the Button is clicked. Other events can be detected and used by the Button, like the pointer entering or leaving the area over the Button, but this requires an additional component.
All of the functions in the function list are called when the Button is clicked. To add a function, click the plus icon to create a new row. To remove one, click the row with the function, even if there is only one, and click the minus icon.
In a row of the function list, the checkbox says whether this function is called by the On Click event. The first field is an object field. Putting a GameObject into the object field lets the event system find all the functions on that GameObject that can be called by On Click. This is done with the object picker or by dragging the object into the field. The function list shows all the components on the GameObject, both built-in components and custom scripts. After the component is selected, a new list shows the eligible functions on it; select the function to be called. The last field is a parameter field for passing an argument into the function; it can be left empty.
To be eligible a function must be public, have the return type void, and have one or no parameters. If it has a parameter, it must be a float, int, string, bool or Unity Object. Unity Object is the base of almost all classes in Unity, including GameObject, Component, MonoBehaviour and more, which makes the object parameter more powerful than it looks at first, because it can accept many things as an argument. If the parameter is a float, int or string, the value is typed into the parameter field. If it is an object, an object is put into the parameter field with the object picker or by dragging. If it is a bool, a checkbox appears.
Example - add a Sphere as the GameObject in the first row, select the MeshRenderer and then set the material; the parameter needs an object reference, so any available material can be chosen. At the same time On Click can call a second function, this time on a Capsule - using the GameObject itself, On Click can call SetActive with the value false.
The most common function to call is a custom one. Custom functions must be public void and have one or no parameters of the types above. The script must be attached to a GameObject, and that GameObject must be put into the object field. The custom script then appears in the list, and the custom function can be selected from it. If there are no parameters, the parameter field is left blank. In Play mode the effect of all the functions is seen when the Button is clicked.
STEPS
- Call a script function from a Button. 1) Write a public void function in a script, with no parameter or one parameter (float, int, string, bool or Unity Object). 2) Put the script on a GameObject. 3) Select the Button. 4) In On Click press plus. 5) Drag that GameObject into the object field. 6) In the function menu pick the script, then the function. 7) Fill the parameter field if the function has a parameter.
- Hide an object on click without a script. 1) In On Click press plus. 2) Drag the object into the object field. 3) Pick GameObject, SetActive. 4) Leave the checkbox off.
WATCH OUT
- Hover and other pointer events are not in On Click; they need an extra component such as an Event Trigger.


CANVAS AND RENDER MODES (Overlay, Camera, World Space, draw order):
SUMMARY
- The Canvas renders a group of UI elements. Three render modes - Screen Space Overlay, Screen Space Camera, World Space.
- Draw order - Hierarchy order inside a Canvas, Sorting Layer and Order in Layer between a Canvas and other renderers.
LESSON
The Canvas is a component that controls how a group of UI elements is rendered. All UI elements must be children of a Canvas. It is possible to have more than one Canvas in a scene, but to use a UI element there must be at least one. If a new UI element is created and no Canvas exists, a new Canvas is created and the new element is attached to it as a child.
Each Canvas has several possible render modes, set with the Render Mode popup menu.
Screen Space - Overlay is the most common render mode and the default. The UI overlays the scene, and all UI elements are drawn on top of everything else rendered in that scene. In this mode the Canvas fills the screen automatically and resizes automatically if the screen settings change. In Overlay mode the Canvas drives the RectTransform, and the entire RectTransform is uneditable; the Canvas sets all its values to fill the screen. This mode has the Pixel Perfect option - UI elements are adjusted to the nearest pixel when rendered, which can in some cases sharpen the look of the UI.
Screen Space - Camera is very similar to Overlay, but it is rendered by a specific camera in the scene. This allows camera-specific settings to be applied to a screen space UI; the most common is using a perspective camera to give the UI a feeling of depth. In this mode the Canvas fills the camera's viewport automatically and resizes if the viewport settings change. The RectTransform is again driven entirely by the Canvas. This mode has several options, including Pixel Perfect, which works the same as in Overlay. Render Camera sets the camera that renders the UI elements on this Canvas. If it is None, the Canvas uses the Overlay settings. When a camera is assigned, the UI elements are moved into the camera's frustum and resized to fit, so the UI can be rendered relative to GameObjects in the scene. Plane Distance moves the Canvas closer to or farther from the camera; the Canvas and its elements are automatically resized to fit the frustum based on their position in front of the camera. Plane Distance must be within the rendering camera's near and far clipping planes to be rendered. In Screen Space - Camera the Canvas can be rendered by any camera in the scene; to isolate a Canvas and its contents from other cameras, use the camera's Clear Flags, Culling Mask and Depth properties.
World Space renders UI elements in the scene volume. These can be static objects in the scene, or mobile objects like speech bubbles or player tags that follow GameObjects. In World Space the Canvas no longer drives the RectTransform, and the Canvas can be placed anywhere in world space. Because there can be more than one Canvas in a scene, it is not uncommon to create new World Space Canvases as needed. Event Camera is required to receive events and decides which camera is used to detect events like clicking on a UI element; in most cases it is the camera rendering the scene. Receives Events says whether the UI elements on this Canvas receive events like clicks and hovers; turn it off to ignore events on all UI elements that are children of this Canvas.
Sorting Layer and Order in Layer control the render order of the Canvas compared to other renderers in the scene. They are exposed on the Canvas component and are available for Canvases set to Screen Space - Camera or World Space.
UI elements on a Canvas are rendered in top-down order - the first items are rendered at the back, and lower items are rendered later and appear on top. To change the order in which a UI element renders, change its order in the Hierarchy.
STEPS
- Normal game menu or HUD. 1) Create a Canvas. 2) Leave Render Mode on Screen Space - Overlay. 3) Order the children in the Hierarchy - background first, popups last.
- UI that mixes with the world or needs camera effects. 1) Set Render Mode to Screen Space - Camera. 2) Assign Render Camera. 3) Set Plane Distance inside the camera's near and far planes. 4) Set Sorting Layer and Order in Layer against the sprites and particles.
- A label that follows an object. 1) Create a new Canvas and set Render Mode to World Space. 2) Assign Event Camera. 3) Size and place the Canvas RectTransform in the scene, or make it a child of the object.


UI SCROLL RECT (scrolling content inside a window, masks, scrollbars, inertia):
SUMMARY
- Scrolls content that is larger than its window - lists, long text. Used with a Mask and Scrollbars.
- Settings - Content, Horizontal, Vertical, Movement Type, Elasticity, Inertia, Deceleration Rate.
LESSON
The Scroll Rect is a UI element that allows the user to move another UI element along the horizontal and/or vertical axes. This is usually a large image or a panel of other UI elements, such as a list of buttons or a large block of text. The Scroll Rect is most often used with a Mask element and is designed to work seamlessly with Scrollbars.
To create a Scroll Rect, add a Scroll Rect script to a GameObject that is the child of a Canvas - Add Component, UI, Scroll Rect. In the lesson the GameObject is renamed Scroll View.
Content is a reference to the RectTransform of the UI element controlled by the Scroll Rect - for example an image far larger than the Scroll Rect. Put the content, here the large image, into the Content property of the Scroll Rect. In Play mode this content is fully scrollable.
The Scroll Rect is commonly used with a Mask. To use a Mask with the Scroll Rect, first add an Image script to the GameObject for the Mask to use, then add a Mask script. The Mask uses the Image to create its mask. A specific image is not needed on the Image script, but one can be added for more control over the shape of the mask.
Horizontal and Vertical enable scrolling along those axes. To disable scrolling along one axis, set that property to false.
Movement Type describes the scrolling mode, chosen in the Movement Type popup menu. Unrestricted allows unrestricted scrolling. It is not a common choice, and without some additional method it is entirely possible to lose the content in a way that cannot be recovered; this mode may still be useful in certain cases. With Elastic or Clamped, the content cannot leave the bounds of the Scroll Rect on any scrollable axis. In these two modes, for the content to be scrollable, the RectTransform of the content must be larger than the RectTransform of the Scroll Rect; if it is smaller, it cannot be scrolled along that axis. When positioning the content in either of these modes, it is best to place the content so it starts within the bounds of the Scroll Rect, or unwanted behavior can occur as the Scroll Rect tries to bring the content back within its bounds.
With Elastic the content bounces when it reaches the bounds of the Scroll Rect; the amount of bounce is set by the Elasticity property. With Clamped the content does not bounce when it reaches the bounds, it simply stops scrolling.
Inertia defines whether the content continues to glide when the pointer is released after a drag. When Inertia is false, the content only moves while dragged. When Inertia is true, the content continues to glide after the drag has ended. How soon the content stops gliding is set by Deceleration Rate - the lowest rate stops the gliding instantly, the highest rate means the gliding never slows down.
Horizontal Scrollbar and Vertical Scrollbar are optional references to Scrollbar elements. To use Scrollbars with a Scroll Rect, create the Scrollbars needed, position them, and put them into these properties on the Scroll Rect. They work automatically.
STEPS
- Masked scroll view by hand. 1) Create a panel GameObject under the Canvas and name it ScrollView. 2) Add an Image and a Mask. 3) Add the Scroll Rect component. 4) Create a child named Content. 5) Drag Content into the Content field of the Scroll Rect. 6) Make Content wider or taller than ScrollView. 7) Turn Horizontal and Vertical on or off.
- Bounce and glide. 1) Select ScrollView. 2) Set Movement Type to Elastic. 3) Set Elasticity. 4) Turn on Inertia. 5) Set Deceleration Rate.
- Add scrollbars. 1) Create a vertical or horizontal Scrollbar. 2) Select ScrollView. 3) Put it into Vertical Scrollbar or Horizontal Scrollbar. 4) Test in Play mode - the handle size and position follow the content.


UI IMAGE COMPONENT (source image, color, Simple, Sliced, Tiled, Filled):
SUMMARY
- Shows a sprite in the UI. Source Image, Color, Material.
- Image Type - Simple, Sliced (9-slice), Tiled, Filled.
LESSON
The Image component is used to give UI elements an actual graphical presence on the screen. Images can make up the backgrounds of buttons, panels, sliders and anything else in a UI composition.
The first property is Source Image - a reference to the sprite the Image displays. With None, the Color is used to draw the outline of the image as a plain shape.
The next property is Color. This color is multiplied with the color of the sprite, so it can be used for fading or tinting a sprite.
By default an Image does not need a material, but one can be added to use the properties of a shader on the Image. The texture property of the material is ignored. Unity provides shaders that can be used with the UI system; to use them, create a material and pick one from the UI group in the shader dropdown.
Image Type affects how the Source Image is used and has several options.
Simple means the sprite just stretches to fit the RectTransform size. Preserve Aspect means the image is as large as it can be within its bounding rect while keeping the aspect ratio it was imported with, so it does not lose its original proportions as it is resized. Set Native Size is available with this option; it sets the RectTransform size to the size of the sprite in Source Image - in the lesson the rect goes back to the original size of the sprite.
Sliced means the image is displayed with the 9-slice method. A 9-sliced sprite is separated into nine sections in a grid pattern. The outer border sections do not stretch while the center does, which allows scaling without distortion of the edges. These sections are defined by the borders set in the Sprite Editor for the texture. Sliced has another property, Fill Center, which toggles whether the center section is shown; this allows designing and rendering only the borders of an image.
Tiled tiles the Source Image starting from the lower left corner of the rect. The lesson uses an unsliced sprite as the example.
Filled shows a proportion of the image defined by the Fill Amount property - at the lowest value none of the image is shown, at the highest all of it is. Filled has several sub-options. Fill Method together with Fill Origin determine which point represents Fill Amount zero and in which direction the image fills as it increases. For radial fill methods, Fill Origin defines where the fill is carried out from, and there is the option to switch between clockwise and anticlockwise. These fills are ideal for health bars, or for car speedometers in the case of radial fills.
STEPS
- A panel that resizes without distorted corners. 1) Select the panel texture and set Texture Type to Sprite (2D and UI). 2) Open the Sprite Editor, set the four border sizes, press Apply. 3) Create UI, Image under the Canvas. 4) Put the sprite into Source Image. 5) Set Image Type to Sliced. 6) Resize the RectTransform - the corners stay sharp.
- Radial cooldown over a skill icon. 1) Create an Image for the skill icon. 2) Create a child Image as the grey overlay. 3) Set the overlay's Image Type to Filled. 4) Set Fill Method to Radial 360. 5) Set Fill Origin to Top. 6) Turn on Clockwise. 7) Change Fill Amount from 1 to 0 from a script or an animation as the cooldown runs out.COOKBOOK - UNITY ANIMATION (Animator, Animation window, Blend Trees). ANIMATOR COMPONENT (Controller, Avatar, Apply Root Motion, Culling Mode):
SUMMARY
- The Animator component animates the properties of a GameObject. It points to an Animator Controller asset.
- Settings - Controller, Avatar, Apply Root Motion, Animate Physics, Culling Mode.
LESSON
To animate the properties of GameObjects in Unity we use the Animator component. Animator components have a number of properties, which may differ depending on what is animated - a 3D humanoid character needs different settings than a 2D sprite.
The first property of the Animator stores a reference to an Animator Controller asset. Animator Controllers are Unity assets that contain one or more state machines, which determine which animation is played while the scene is running. These state machines can be on multiple layers and use parameters of various types to decide when they transition between states and blend. For example, the parameters of an Animator Controller can be set from scripts to tell it if the character is running, jumping or shooting. It then plays and blends the animations automatically.
The Avatar is an asset that Unity creates when importing a 3D humanoid. It contains the definition of the skeletal rig of the character. When a character of this type is added to the scene, the Avatar field is filled in automatically with the asset created for that character. Think of the Avatar as the glue that binds the model to the Animator. For generic objects without skeletal rigging an Avatar is not required.
Apply Root Motion determines whether the animation can affect the transform of the GameObject, and is generally used with 3D humanoids. Root motion is the core movement within an animation clip. Imagine the difference between a character running on the spot and one that is animated running a few paces forward. In the second case the forward motion of the character can drive the character around the game, looping that clip for realistic continuous motion. If the animations run on the spot, Apply Root Motion is unchecked and the character is moved from a script instead. This property can also be overridden entirely - by creating a script with the OnAnimatorMove function and attaching it to the GameObject.
Animate Physics can be checked or unchecked. When checked, the animations are executed in time with the physics engine. This is generally advised if the animated object has a Rigidbody.
Culling Mode affects whether the animations are played while the object is not being rendered. Always Animate means the animations play even while not rendered. Based On Renderers means the animation only plays while rendered - when the character is hidden from view, animation stops to save performance. With either option the root motion is applied as normal - if a character was walking with root motion applied, it continues to move while not rendered, so it ends up in the correct place when it becomes visible again.
STEPS
- Animate a 2D sprite or a UI object. 1) Add an Animator component. 2) Assign an Animator Controller. 3) Leave Avatar empty. 4) Leave Apply Root Motion off - the object is moved by the animation of its own properties or by a script.
- Save performance on objects that leave the screen. 1) Select the object with the Animator. 2) Set Culling Mode so animation stops when the object is not rendered.
WATCH OUT
- Newer Unity versions name the Culling Mode options Always Animate, Cull Update Transforms and Cull Completely, and Animate Physics is a choice in Update Mode.


ANIMATOR CONTROLLER, STATES AND TRANSITIONS (parameters, Has Exit Time):
SUMMARY
- An Animator Controller is a state machine that decides which animation plays. States hold animation clips, transitions move between states, parameters drive the transitions.
- Parameters - Float, Int, Bool, Trigger. Transition settings - Has Exit Time, Conditions, Solo, Mute.
LESSON
Animator Controllers contain one or more state machines that determine which animations are currently being played. The states are controlled by parameters, which get their values from scripts.
To create an Animator Controller click the Create menu in the Project view and select Animator Controller, or right-click any blank space in the asset view and select Create, Animator Controller. Animator Controllers are managed in the Animator window. To open it, click Window, Animator, or double-click any Animator Controller asset. The window is resizable and dockable.
Parameters are created with the plus icon next to the word Parameters. They can be floats, ints, booleans or triggers. Parameters generally represent qualities of an animation or a decision-making condition. For example, when animating a humanoid's movement, a common approach is a float parameter for Speed - when Speed is large, the Animator Controller can be made to transition to states with faster animations.
States can be made in one of three ways. The first is to drag an animation clip from the Project panel onto empty space in the Animator window; this creates a state whose motion is that clip. The second is to right-click empty space in the Animator window and select Create State, with three options - Empty, From Selected Clip, and From New Blend Tree. An empty state is one that has no motion; these can be useful because they do not mask animation that is played on other layers. To create a state from a selected clip, the animation must be highlighted in the Project panel. The third way is to create an animation in the Animation window, which is separate from the Animator window; when the animation is created, a state for it is created in the Base Layer of the Animator Controller the animation is made for.
The first state created on any layer becomes the default state, shown by the state's orange color. The default can be changed by right-clicking another state and selecting Set as Default. The default state is the one whose animation is played at the start.
To edit a state, click it and use the Inspector. At the top are a name and a tag for the state. Both can be referenced from code to perform actions while in specific states, so it is a good idea to set them to something meaningful. Speed is how fast the animation plays compared to its normal playback speed; a value of 1 is normal speed. Motion is the animation clip for the state. Foot IK stands for foot inverse kinematics; if checked, it reduces or eliminates foot slipping in the animation. Mirror flips the animation left to right. Below this is the list of transitions from this state to others.
A transition allows the Animator Controller to move smoothly from one animation clip to another. We can specify when and how to transition, which gives a high level of control. To create a transition, right-click the state to transition from and select Make Transition; a transition arrow is attached to the cursor; click another state to complete it. Click the transition to edit it in the Inspector.
Each transition has the options Solo and Mute. Mute effectively disables the transition. Solo takes into account all the transitions that come from the same state and effectively mutes all those that are not marked as Solo. Mute and Solo are tools for debugging and for focusing on particular areas of state machines. They should not be checked in any published build.
Below those properties the transition can be given a name. Under that is the Atomic property - if checked, the transition cannot be interrupted by other transitions.
The graph shows how the animation is handled during the transition. The scale is in seconds and frames. There are three markers on the scale - the start and the end of the transition in time, and a scrubber for previewing the animation of the transition. Between the start and end markers is a blue shaded region, which is the transition from one animation to the next. The graph curves show which foot is the most stable over time. For a state with a running animation the curve changes from up to down and back. If the line is in the center, as in an idle animation, neither foot is more stable. For a smooth transition try to get the lines to match up; if neither foot is more stable, this is less important. The two states can be moved back and forth in the graph to adjust at what points the transition starts and ends.
Below the graph is where the condition that causes the transition is set. By default transitions have a condition of an exit time - once the animation of a state is a portion of the way through, it transitions to the next state. Conditions generally depend on parameters - a bool parameter being true or false, or a float parameter being greater than or less than some constant value. A transition can have multiple conditions; click the plus button to create more. At the bottom of the Inspector there is a preview window for viewing what the transition looks like.
It is possible to have multiple transitions to and from the same states. Generally this is used to have several sets of conditions for the same change. Consider a Speed parameter and two states, Idle and Run. To transition from Idle to Run when Speed is not zero, create two transitions - one with the condition that Speed is above a small positive value, and one that Speed is below a small negative value.
STEPS
- Idle to Run with a Speed parameter. 1) In the Project view create an Animator Controller and name it. 2) Double-click it to open the Animator window. 3) In Parameters press plus, Float, name it Speed. 4) Drag the Idle clip into the graph - it becomes the orange default state. 5) Drag the Run clip into the graph. 6) Right-click Idle, Make Transition, click Run. 7) Select the arrow, turn off Has Exit Time so the reaction is instant, add the condition Speed Greater than a small value. 8) Right-click Run, Make Transition, click Idle. 9) Turn off Has Exit Time, add the condition Speed Less than that small value.
- Find which transition misbehaves. 1) Select the transition arrow. 2) Check Mute to switch that transition off while testing in Play mode. 3) Or check Solo to test only that one path out of several. 4) Before a build, make sure every Solo and Mute checkbox is off.
WATCH OUT
- Several conditions on one transition must all be true together. Several transitions between the same two states are alternatives - any one of them can fire.
- Atomic is from older Unity versions. Newer versions control interruption with the Interruption Source setting of the transition.
- A transition with Has Exit Time on waits for the clip; turn it off when the animation must react to input at once.


ANIMATOR LAYERS (Weight, Mask, Override or Additive, Sync):
SUMMARY
- Layers split the state machines of an Animator Controller so that different body parts or extra motion can be animated at the same time.
- Settings of a layer - Name, Weight, Mask, Blending (Override or Additive), Sync, Timing, IK Pass.
LESSON
The state machines of Animator Controllers can be split into layers. These are generally used to animate different body parts. For example, the base layer can handle the overall movement of a character, while a separate waving animation is handled on another layer, so the character can move and wave at the same time.
By default an Animator Controller has one layer called Base Layer. The only adjustable properties of this layer are its name and whether it does an IK pass. IK is short for inverse kinematics. When a layer does an IK pass, the OnAnimatorIK function is called for that layer with the layer index. The Base Layer has index 0, and additional layers have indices starting at 1 and counting upwards.
Later layers have additional options about how they react to previous layers. A new layer is created with the plus icon next to the word Layers. All layers have a name, set with the Name property.
Weight is how much the layer affects the final animation. With no weight the layer does not affect the animation at all; with full weight it changes the animation completely. Layers with higher weights have priority over lower ones. The slider sets the default value of the weight, but it can still be set from code at runtime with the SetLayerWeight function of the Animator class.
Mask defines which Avatar Mask, if any, the layer uses to isolate body parts for animation.
Blending of a layer can be Override or Additive. With Override, the resulting animation overrides the animation of the lower layer, as defined by the weight. With Additive, the animations on this layer are added to, or combined with, the animations of the lower layers. An example is a layer for a character breathing heavily as they become tired - the heavy breathing animation is added to the animation on the lower layers. The weight can measure how tired the character is - as the weight of the layer increases, the heavy breathing becomes more apparent.
The last option of a layer is Sync. When Sync is checked, you choose which layer to sync with. This creates a state machine identical to the one on the selected layer, but with no motions, so the Animator is always in the same state in both layers. This can be used for things like wounded behavior - with one set of animations for a healthy character and one for a wounded character, they can be blended as the character loses health. The Timing checkbox allows the Animator to adjust how long each animation in synced layers takes, determined by the weight.
STEPS
- A second action on top of movement, like waving while walking. 1) In the Animator window press plus next to Layers. 2) Name the layer. 3) Assign an Avatar Mask that includes only the arm. 4) Leave Blending on Override. 5) Add the Wave state on this layer, with an empty default state. 6) Set Weight to full, or change it from a script when the wave starts and ends.
- A second set of animations for the same states, like a wounded character. 1) Add a layer. 2) Check Sync and pick the Base Layer. 3) Put the wounded clips into the copied states. 4) Raise the layer Weight as health drops.
WATCH OUT
- On the Base Layer only the name and IK Pass can be changed; Weight, Mask and Blending exist only on the added layers.


BLEND TREES (1D and 2D blending of clips by parameters, thresholds):
SUMMARY
- A Blend Tree mixes two or more animations by a parameter - for example walk and run by Speed, or left, forward and right by direction.
- Types - 1D, 2D Simple Directional, 2D Freeform Directional, 2D Freeform Cartesian. Per motion - Threshold, Time Scale, Mirror.
LESSON
Sometimes when animating you want a mix of two or more animations. For example, with animations for running left, running forward and running right, you might want running only slightly to the left or right. Another common example is having walking and running animations and wanting the character to move at speeds between the two. Blend Trees can be used for this.
To create a Blend Tree, right-click empty space in the Animator window and choose Create State, From New Blend Tree. This creates a state that has a Blend Tree as its motion instead of a single animation. Double-clicking the state opens the Blend Tree for editing. The breadcrumb in the upper left corner shows that we are inside the Blend Tree; clicking the Base Layer name goes back out.
With the Blend Tree selected, its properties are in the Inspector. Blend Trees have names, which can be different from the state that holds them. Next is the Blend Type.
One-dimensional Blend Trees use a single parameter to control how much of each motion is played. For running left or right the parameter might be direction or angular speed; for walking and running it could be Speed.
Next is the list of motions. To add motions click the plus icon, which gives the options Add Motion Field and New Blend Tree. New Blend Tree allows nested Blend Trees, so animations can be blended by more than one parameter; an easier approach for that is usually a two-dimensional Blend Tree. Each motion field represents an animation; it can be dragged in from the Project panel or selected with the circle select button.
Each motion field has three properties. Threshold is the value of the chosen parameter at which the blend uses entirely this animation. For example, walking has a low threshold and running has a higher one - when Speed reaches the running threshold, the Blend Tree plays just the running animation; halfway between the two it plays an even blend of walking and running. Time Scale affects the speed the animation is played at, the same as the Speed property of normal states. The last property decides whether the animation is mirrored left to right.
After motion fields are added, a blue diagram appears above the list of motions. It shows where the motions lie on the scale of the parameter - the lowest threshold on the left, the highest on the right. The red scrubber previews the blended animation for different values. To change the order of the motions, drag them with the handle on the left.
Below the list of motions are a few properties that help adjust the motions. Generally it is a good idea to use them after all the motion fields are added and have animations. If Automate Thresholds is checked, the thresholds of each animation are set and cannot be changed. If it is unchecked, the next two options can be used. Compute Thresholds calculates and sets the thresholds of each motion field based on a chosen property of root motion - Speed, Velocity X, Velocity Y, Velocity Z, or Angular Speed in radians or degrees. Because Blend Trees often have thresholds based on these root motion properties, these are also common Animator parameters. Adjust Time Scale can make the speed of each animation homogeneous - each of the animations then results in the same speed of root motion.
Two-dimensional Blend Trees work very much like one-dimensional ones, but blend by two parameters instead of one. There are three types. The first two are for blending based on direction - 2D Simple Directional and 2D Freeform Directional. The last type is 2D Freeform Cartesian, used when the parameters do not represent direction. 2D Simple Directional is for blending movement by directional parameters with a single animation in each direction, such as walk forward, walk back, walk left. 2D Freeform Directional is used similarly but can include multiple animations in the same direction, for example walk forward and run forward. 2D Freeform Cartesian is used when the parameters are not based on direction, for example Speed and Angular Speed.
Creating each of these types works the same. After choosing a type, choose one Animator parameter for the X axis and one for the Y axis. For the directional types a standard X parameter is Velocity X and a standard Y parameter is Velocity Z. For Freeform Cartesian the choice is more open. Then add motions, just as with 1D Blend Trees; they can be Blend Trees or motion fields. Unlike 1D Blend Trees, the order in which they are added does not matter.
After motions are added, a diagram shows where the motions are according to their thresholds. It works like the 1D diagram, but because it is based on two thresholds, an X threshold and a Y threshold, it is in two dimensions. Each motion can be positioned by dragging it on the diagram, by setting the thresholds by hand, or with the Compute Positions option, which works like Compute Thresholds for 1D but computes the thresholds from both parameters. 1D Blend Trees use a red scrubber for the preview; 2D Blend Trees have a red dot that can be dragged around.
STEPS
- Walk and run in one state (1D). 1) Add a float parameter Speed. 2) Right-click the Animator window - Create State, From New Blend Tree. 3) Double-click the state to open it. 4) Select the Blend Tree; set Blend Type to 1D and Parameter to Speed. 5) Press plus, Add Motion Field, twice. 6) Put the Walk clip in the first field and the Run clip in the second. 7) Turn off Automate Thresholds and type the thresholds, or use Compute Thresholds, Speed. 8) Drag the red scrubber to preview the blend.
- Eight-direction movement (2D). 1) Create a Blend Tree state and open it. 2) Set Blend Type to 2D Freeform Directional. 3) Choose Velocity X for the X parameter and Velocity Z for the Y parameter. 4) Add motion fields for forward, back, left, right, idle and the diagonals. 5) Use Compute Positions, Velocity XZ. 6) Drag the red dot to preview.
WATCH OUT
- With Automate Thresholds on, the thresholds are spread evenly and cannot be edited; turn it off to set them by hand.


ANIMATION WINDOW (creating clips inside Unity, keyframes, Dope Sheet, Curves):
SUMMARY
- The Animation window creates and edits animation clips directly in Unity - for cameras, UI, props and other objects.
- Tools - clip dropdown, Add Property, timeline and scrubber, Record, Play, keyframes, events, Samples, Dope Sheet and Curves modes.
LESSON
The Animation view allows creating and modifying animation clips directly inside Unity. It is designed as a powerful and straightforward alternative to external 3D animation programs. For instance, to have a camera fly around a scene and give the player an overview of a level, that animation can be created in Unity.
The lesson has a scene with a camera in the corner and creates an animation that moves the camera from one side of the scene to the other. Because the animation is for the camera, the camera must be selected in the Hierarchy. The Animation view is opened with Window, Animation. Like any other view it is movable, resizable and dockable.
First is the animation dropdown, where the different animations are selected for editing. With no animations yet, the dropdown is blank except for the option to create a new one. When a new animation is created, Unity asks for a name and a location for the animation file. The lesson creates an animation called Camera Flythrough in the Animations folder.
The Add Curve button chooses which components of the object, or of any child objects, are modified by the animation. Each component can be expanded to see more options. To add a curve, click the plus sign next to the item. For a camera flying around the scene, add the Transform's position and rotation.
The timeline is where the timing of the animation is set. It is measured in frames and seconds. The red scrubber chooses the frame to modify.
Next are the Record and Play buttons. When Record is pressed, changes made to the chosen object in the Scene view are added automatically to the animation at the currently selected frame. Play previews the animation. The left and right arrows move through the keyframes of the animation. Next are the buttons that add keyframes and events at the currently selected frame.
The Sample property determines how many frames make up 1 second of animation. Reducing this number makes the animation slower.
At the bottom are two buttons that switch between Dope Sheet mode and Curves mode.
With Record pressed it is very easy to rough out the animation - select the frame to modify and set the desired camera position and rotation in the Scene view. A keyframe is added to the timeline with those values. Properties that are currently being animated are highlighted in red in the Inspector. Continue doing this for the different phases of the flythrough. To preview, click the Play icon next to the Record icon.
To fine-tune the animation, use the Curves mode - select the Curves button at the bottom of the Animation view. The curves of the animation are shown when the component is selected on the left. Again a frame is selected with the red scrubber on the timeline. To modify a value on a curve, click and drag a keyframe to the new value. To create a new keyframe, click the create keyframe button or double-click the curve. Right-clicking a keyframe shows its options. The most notable is Free Smooth - it creates two handles around the keyframe which are used to smooth the curve. Another way to control curves is the Broken option, which allows controlling each side of the keyframe independently. In the lesson a little variance is added to the X position of the Transform, to give the animation a more weightless feel, by creating keyframes on the X position curve and changing the values by hand.
Animations created in Unity have the same Inspector settings as animations made in external programs; they are seen by selecting the clip in the Project view. Because the camera should fly across the screen only once, Loop Time is unchecked.
An Animator is in charge of animation playback for generic objects, the same as for humanoids. Unity automatically adds an Animator to the camera, creates an Animator Controller with a state machine, and assigns it to the component. The clip just created is added to the state machine as the default clip that is played at runtime. This means other clips can be recorded and the Animator can decide when to play them. When the clip is complete, run the scene to see it in action.
STEPS
- A one-time move, like a camera flythrough or a UI panel sliding in. 1) Select the object in the Hierarchy. 2) Open Window, Animation. 3) In the clip dropdown choose Create New Clip and save it. 4) Click Add Property and add the properties, for example Transform Position and Rotation. 5) Press Record. 6) Put the scrubber at frame 0 and set the starting values. 7) Move the scrubber to a later frame and set the next values - a keyframe is added. 8) Repeat for the other points. 9) Press Record again to stop recording. 10) Press Play to preview. 11) Select the clip asset in the Project panel and turn off Loop Time.
- Make the motion smooth. 1) Switch from Dope Sheet to Curves. 2) Select the property curve on the left. 3) Find the keyframe where the motion looks harsh. 4) Right-click it and choose Free Smooth. 5) For a sharp change of direction choose Broken and move the two handles separately.
WATCH OUT
- In current Unity versions the Add Curve button is called Add Property.
- A new clip loops by default; turn off Loop Time on the clip asset for an animation that should play once.


ANIMATION CURVES AND ANIMATION EVENTS (values over a clip, function calls):
SUMMARY
- A curve on a clip defines a value over the length of the animation that a script can read. An event calls a script function at a chosen point of the animation.
- Both are set at the bottom of the Animations tab of a model - Curves and Events.
LESSON
In addition to other properties, animation clips have curves and events. They are found at the bottom of the Animations tab when a model is selected in the Project panel.
Curves can define values over the length of an animation. For instance, in a jumping animation a height value can be defined on a curve, set to match the height of the model's torso during the jump. That value can then be read in scripts and used to adjust the size of the model's collider, so the collider accurately follows the model's movement.
To add an animation curve to a clip, expand the Curves dropdown and click the plus icon. Then name the curve - in the example, something like Jump Height. This curve name must also be added as a float parameter to any Animator Controller that uses the curve, or it cannot be accessed.
There are two ways of editing the curve itself. Clicking the image of the curve opens the curve editor; this is the best way for fine-tuning a curve or when accuracy is important. In the curve editor, double-click the line to create a keyframe, and drag keyframes to the right values. The curve can be reset by clicking one of the default curves at the bottom. The other way is to scrub through the animation with the preview window's scrubber and set keyframes at the right times with the button just left of the curve. To the left of the keyframe button is the value display, where the value of that keyframe is set. The left and right buttons below the name move between the keyframes. Unity then makes a smooth curve between them automatically.
When blending between multiple clips, each with a curve of the same name, an average value is taken based on the weight of the blending.
To read the value of a curve in a script, use the GetFloat function of the Animator component. It takes either the name or the name hash of the curve as a parameter. The return value is the value of the curve at the moment the function is called.
Events allow calling functions in scripts at different points in an animation. For instance, in a jumping animation we may want to play a sound when the model lands. This is done by creating an event at the point in the animation where the model's feet land on the ground.
To add an event, expand the Events dropdown, scrub through the animation with the preview scrubber, and add events with the button to the left of the timeline. This opens a window with the properties of the event. The first is the name of the function that is called. It must be a function in a script that is attached to the same GameObject as the Animator component that plays the animation. In the example the script has a function called PlayLandingSound, so PlayLandingSound is typed in the Function property. The following properties are possible parameters for the function. Only one can be used for a function call; which one depends on the parameters of the function being called.
When blending between clips with events, all of the events are called, so keep that in mind. If an event plays a sound effect such as a footfall, limit the number of times it can be played by checking whether the sound is currently playing before playing it again; otherwise several copies of the same sound are likely to play at the same time.
STEPS
- A curve that a script reads, like jump height for a collider. 1) Select the model in the Project panel. 2) Open the Animations tab and select the Jump clip. 3) Expand Curves and press plus. 4) Name the curve JumpHeight. 5) Click the curve preview to open the curve editor. 6) Add keyframes - flat at the start, the peak value at the top of the jump, flat again at the landing. 7) Press Apply. 8) In the Animator Controller add a Float parameter with exactly the same name, JumpHeight. 9) In the script read the value every frame and apply it to the collider height.
- A sound at a foot step without doubled sounds. 1) Select the model and open the Animations tab. 2) Select the Run clip and expand Events. 3) Scrub to the frame where the left foot touches the ground. 4) Press Add Event and type the function name, for example OnFootstep. 5) Repeat for the right foot. 6) Press Apply. 7) Put a script with an OnFootstep function on the same GameObject as the Animator. 8) In that function play the sound only if it is not already playing.
WATCH OUT
- A curve without a Float parameter of the same name in the Animator Controller cannot be read.
- The event function must be on the same GameObject as the Animator, or it is not found.


ANIMATOR SCRIPTING (setting parameters from code, hash IDs, current state):
SUMMARY
- A script changes Animator parameters to make the controller switch states. Float, Bool and Trigger parameters each have their own set function.
- Hash IDs are a faster way to name a parameter or a state than a string.
LESSON
To affect transitions between the states of an Animator Controller, the Animator parameters must be set to the right values. This is done with functions of the Animator class.
The lesson has a scene with a model named Ethan. Ethan has an Animator component and a script. The Animator uses a controller with four states - Idle, Walk, Run and Jump - and two parameters, a float named Speed and a trigger named Jump. The controller is set up so that Ethan transitions from Idle to Walk to Run based on Speed. If Jump is triggered while Ethan is running, Ethan enters the Jump state. All the animations of the model are controlled by these two parameters.
In the script, first create an Animator variable, named anim, to hold the Animator. A reference to the Animator is taken in the Start method with GetComponent.
The controller is set up so that Speed decides which moving animation plays, and the player's input controls that. In the Update method create a float variable, move, and set it to the vertical input axis with Input.GetAxis("Vertical"). Then pass the value of move to the Speed parameter of the controller with the SetFloat function of the Animator. SetFloat is used because Speed is a float parameter. For a boolean parameter it would be SetBool, for a trigger SetTrigger, and so on. Each of these functions can be called in several ways. The most common is to pass the name of the parameter as a string first, then the value to set. Here it is anim.SetFloat("Speed", move). In Play mode, pressing W or the up arrow now moves the model - the Speed parameter and the movement animation are controlled by the player.
Passing a string name for the parameter can be inefficient, because the Animator has to evaluate the string every time it is called. A faster way is hash IDs. Each string an Animator can use is given a hash ID - an integer that is unique for every different string. We can store this value and set parameters with the ID instead. Create an integer variable, jumpHash, and get its value with the static method Animator.StringToHash, passing the string whose hash ID we want.
To make the model jump, the Jump trigger parameter must be set. The model should jump when the space bar is pressed, so check Input.GetKeyDown(KeyCode.Space), and inside the if statement call anim.SetTrigger(jumpHash). Because Jump is a trigger, no value is passed. In Play mode the space bar now makes the running model jump.
Sometimes the logic needs to know which state the controller is in. For example, the Jump trigger should be set only when the model is in the Run state. Create an AnimatorStateInfo variable, stateInfo. The AnimatorStateInfo class stores the name, the hash and other information about a state. Set stateInfo to anim.GetCurrentAnimatorStateInfo, passing the index of the layer - 0 for the base layer. The state's name could be compared with a string, but comparing hash IDs is more efficient. Create an integer runStateHash and set it with Animator.StringToHash("Base Layer.Run"). The "Base Layer." part is needed because states with the same name can exist on different layers. Then change the if statement so the model jumps only if the state's hash equals runStateHash.
STEPS
- Drive an animation from a script. 1) Keep a reference to the Animator, taken once at the start. 2) Each frame set the Float parameter from the input or the game data. 3) For a one-time action set the Trigger parameter with SetTrigger. 4) Keep the hash IDs of the parameter names in variables and pass them instead of strings.
- Do something only in one state. 1) Read the current state info of layer 0. 2) Compare its hash with the stored hash of "Base Layer.Run". 3) Act only when they match.
WATCH OUT
- The lesson compares the state with the old nameHash property. In current Unity versions the hash of a full path like "Base Layer.Run" is compared with fullPathHash, and the hash of the short name "Run" with shortNameHash.
- A Trigger stays set until a transition uses it. Setting it when no transition can use it makes the action happen later, at the wrong moment.


MODEL IMPORT - ANIMATIONS TAB (clips from a model file, looping, root motion):
SUMMARY
- The Animations tab of a model decides how Unity imports the animations stored in the model file - which clips exist, how they loop, how they are compressed.
- Settings - Import Animation, Bake Animations, Anim. Compression, Clips, Start, End, Loop Time, Loop Pose, Cycle Offset, Root Transform Rotation and Position, Mirror.
LESSON
With a model highlighted in the Project panel, the Inspector defines how Unity interprets the mesh, animation and other properties. These properties come in three parts - Model, Rig and Animations. This lesson looks at the Animations section.
The first option is whether to import animations. It must be checked to use any of the animations stored in the model file.
Bake Animations is used when an animation was created in a separate modeling or animation program using inverse kinematics, IK for short, and has not yet been converted to forward kinematics.
The compression of the animations can also be chosen. By default there is no compression, but Keyframe Reduction or Optimal can be chosen. With compression, decide what error is allowed for position, rotation and scale - the smaller the values, the higher the precision, but the less compression.
Below the compression options is a list of clips available from the model. Clips can be added or deleted with the plus and minus icons. Next to each name are the start and end frames of the clip; this is what makes each clip in a take different.
When a clip is selected, all the options for that specific clip are available. The first is the name of the clip. If the file has multiple takes, it also shows which take the clip is from. Next is the timeline of the animation - with the handles on the timeline, or the Start and End fields, set on which frame the clip begins and ends.
Below Start and End are the loop controls. Loop Time, when checked, means that when the animation finishes playing it starts again. If Loop Pose is checked, Unity tries to match up the start and end pose so the looping clip looks smooth. Cycle Offset adjusts when the clip starts and ends. Use it for mirroring animations - for example, for a mirrored run clip set the offset to half a cycle so that the other foot is on the floor.
Root Transform Rotation affects how the rotation in an animation affects the Avatar. If the root transform rotation is baked into the pose, the Avatar does not rotate with any turning in the animation. Use this for animations such as running in a straight line, so that a slight deviation from a straight line does not affect it. It can be based on Body Orientation at the start of the animation or on the Original source file. With Body Orientation the upper body points forward. The Offset fine-tunes the direction of the animation.
The next options are about Root Transform Position on the Y axis. As with rotation, with Bake Into Pose checked the Avatar does not move up or down during the animation. The position can be based on Original, which takes the Y position from the source file, on the Avatar's Center of Mass, or on the position of its Feet. The Offset fine-tunes the movement on the Y axis.
Root Transform Position XZ works like the Y options but affects the horizontal movement of the Avatar. Baking into the pose restricts movement on the XZ plane. It can be based on the Original file or the Center of Mass.
When the handles on the timeline are used to adjust the animation, a graph appears for each of these properties, showing how well it matches when the clip is looped. Each option has a traffic light - green for a good loop match, yellow for an okay match, red for a bad match. Depending on the clip, you may or may not want these to loop nicely. With a walking animation the pose should loop nicely, but the transform position XZ probably should not loop.
If the Mirror box is checked, the animation is flipped left to right.
STEPS
- Several clips from one model file. 1) Select the model in the Project window. 2) Open the Animations tab. 3) Check Import Animation. 4) Under Clips press plus. 5) Select the new clip and name it. 6) Set Start and End with the timeline handles or the frame fields. 7) Check Loop Time and Loop Pose for a looping clip. 8) Look at the traffic lights - aim for green on Loop Pose. 9) Press Apply.
- A character that runs straight and stays on the ground. 1) Select the clip in the Animations tab. 2) In Root Transform Rotation check Bake Into Pose and set Based Upon to Body Orientation. 3) In Root Transform Position (Y) check Bake Into Pose and base it on Feet. 4) In Root Transform Position (XZ) leave Bake Into Pose off if root motion should move the character, or check it if a script moves the character.
WATCH OUT
- Changes in the Animations tab are not saved until Apply is pressed.

UNITY PROFILER (CPU Usage, Timeline, CPU or GPU bound, VSync, profile a build):
SUMMARY
- The Profiler records what happens in every frame and shows where the frame time goes - scripts, physics, rendering, waiting.
- Tools - CPU Usage chart, Timeline view, Hierarchy view, threads, Development Build with Autoconnect Profiler, save and load of captures.
LESSON
The Profiler is for creators who want to improve gameplay performance with optimization. It is recommended to set a target frame rate for the game and benchmark against it during development. Depending on the case this may be a higher frame rate for desktop and a lower one for mobile. The Profiler shows whether the gameplay meets the target frame rate. Profiling should be done at regular intervals through the whole production.
A quick way to check performance is the Stats option in the Game view, which displays the current FPS.
To understand what happens in each frame, look at the order of execution for event functions. The game loop happens every frame - physics, input events, game logic, scene rendering, GUI rendering, and then the frame is shown. The work is shared between the CPU and the GPU, which must work together to render the frame. Every target frame rate gives a time budget for one frame - the higher the frame rate, the less time each frame has.
The CPU handles the Unity engine code and the game code. The render commands are passed to the GPU to render the frame. When the CPU takes too long to run the game logic, it is a CPU bound bottleneck - the graphics card has to wait for the render instructions. A GPU bound bottleneck happens when the GPU takes too long to render the previous frame, so the CPU has to wait until the GPU is ready.
The Profiler is opened from Window, Analysis, Profiler. It is ready to record, so when Play starts it records data frame by frame. Clicking in the CPU Usage chart pauses the game and selects that frame for analysis.
A game that is not maximized can look faster than it really is. Where possible, profiling should be done at the resolution the game is meant to be played at. For several resolutions, profile each one in turn.
The CPU chart is a combined view of categories, which are color mapped to the colors in the Timeline. When profiling inside the Unity Editor, the running of the Editor is combined with the running of the game. The Others category contains the Editor data alongside other things. It is much better to profile an exported build, which has no Editor data and gives more accurate results. Any category can be viewed in isolation. There are several modules, such as rendering, memory, audio, video; they can be switched on or off as needed.
The Timeline gives an in-depth look at one frame. Click in it and press A to frame all. It shows horizontally the time of each CPU thread in this frame. The main thread runs the game logic and prepares the render commands. The render thread takes the render commands and passes them on to the GPU. Both threads run on the CPU. There is also an Editor marker when profiling inside Unity. Click a profile marker and press F to frame it. If something on a thread takes too long, it can be identified here.
The CPU also hands some work to the Jobs section. This uses the processor cores and multithreading to speed things up. Each worker is a separate worker thread that runs jobs at the same time. The number of workers depends on the CPU cores of the machine and the threading settings of Unity.
Click a profile marker and choose Show in Hierarchy. This moves to the table based Hierarchy, where each process is shown in a parent and child structure with its share of the frame time. Any thread can be chosen, such as the render thread. The table can be sorted from highest to lowest, which makes it easy to see what takes the most time. A dropdown jumps back to the Timeline.
VSync prevents screen tearing. Tearing happens when the top part of the frame is new and the bottom part still comes from the previous frame, which creates a visible tear. VSync forces the graphics card to wait for complete frame data before showing a frame. VSync is enforced on mobile devices; on desktop it can be switched on or off. With VSync on, the frame rate is capped, and the Profiler shows a long waiting marker - the CPU waits for the rest of the frame time before the next frame.
The lesson then shows a scene with no optimization. Cubes have several real time lights with shadows; more real time lights put more stress on the GPU. Spawn points create spheres with Rigidbody physics every frame, several per spawn point, which puts a lot of stress on the CPU. A rotate script calls Debug.Log every frame, which adds more CPU stress.
This scene is profiled from a build, which gives the most accurate results. In the build settings the scene is in the build, Development Build is on, and Autoconnect Profiler is on. With the Profiler open in Unity, the build is started and the Profiler connects to it.
The capture shows spikes that push the frame rate down. In a spike frame, the game scripts take the largest part of the frame, and physics also takes a big part. Physics runs in fixed update. Because many spheres with Rigidbody physics are spawned every frame, physics has to run several times to catch up, which makes the spikes. The render thread has to wait most of the frame before it can render - this is a CPU bound bottleneck. In the Hierarchy, the rotate update is slow only because of Debug.Log.
The fixes - only one light per cube; the Debug.Log is commented out; spawning is moved from every frame to a function that runs every two seconds with InvokeRepeating, which also reduces the physics work. After that the game holds the target frame rate. The scripts take a tiny part of the frame, physics takes a small part, and most of the frame is waiting for VSync, so the CPU is idle for most of each frame.
Debug.Log calls are useful during development, but comment them out before profiling and remove them from the final game.
Saving data as a benchmark is important. A before and after comparison shows that the changes really improve performance. Profiler data is saved with the save icon and loaded with the load icon. It can also be shown to the team.
For mobile games, profile on the mobile device itself. The target dropdown in the Profiler selects the connected device, directly or by IP address.
A flowchart in the Unity profiling e-book helps to decide whether the bottleneck is CPU bound or GPU bound, and gives tips for each case.
STEPS
- Profile a build instead of the Editor. 1) Open the build settings. 2) Make sure the scene is in the build. 3) Turn on Development Build. 4) Turn on Autoconnect Profiler. 5) Open Window, Analysis, Profiler in the Editor. 6) Build and run - the Profiler connects by itself.
- Find what causes a spike. 1) Play and watch the CPU Usage chart. 2) Click a tall spike - the game pauses on that frame. 3) In the Timeline press A to see the whole frame. 4) Look for the widest blocks on the main thread. 5) Click a block and press F to zoom into it. 6) Right-click it and choose Show in Hierarchy. 7) Sort the table by time and read which script or system is on top.
- Decide CPU bound or GPU bound. 1) Look at the main thread in the Timeline. 2) If the scripts, physics or render commands fill the frame and the render thread waits, the CPU is the limit. 3) If the main thread mostly waits for the GPU to finish, the GPU is the limit. 4) A long wait for the target frame rate with VSync on is not a problem - the frame is simply done early.
- Check that a fix worked. 1) Save the capture before the change. 2) Make one change. 3) Record again in the same place of the game. 4) Compare the two captures.
WATCH OUT
- In Unity 6 these build options are in the Build Profiles window, opened from File, Build Profiles.
- Numbers from the Editor are higher than in a build, and a PC is not a phone - the final judgment comes from the target device.


PROFILE ANALYZER (many frames at once, markers, compare two captures):
SUMMARY
- The Profiler looks at one frame. The Profile Analyzer looks at a range of frames and compares two sets of data, for example before and after an optimization.
- Tools - Pull Data, frame range selection, Frame Summary (max, min, median, mean), Top 10 markers, Marker Summary, Total or Self, thread selection, filters, Compare, save and load.
LESSON
The Profile Analyzer gives structured data across a range of frames of the game. It is used to monitor performance and to find where optimization is needed. It can compare two sets of data and show the performance differences.
It is installed from the Package Manager, Unity Registry. It is opened from Window, Analysis, Profile Analyzer. It works alongside the Profiler, so the Profiler is opened too. The Profiler records frame by frame data in Play mode. Then the data is pulled into the Profile Analyzer.
The Profiler inspects individual frames. The Profile Analyzer inspects a range of frames and prepares the analysis by itself. They work closely together.
The Frame Summary shows the selected range and displays the max frame, which is the tallest spike, the min frame, the median frame and the mean, which is the average frame. There are buttons next to max, median and min. Clicking the median button moves the Profiler to that frame, for a deeper look at it.
Click and drag in the graph to select a range of frames, for example the frames around some spikes. The analysis updates for that range. Right-click the range and choose Zoom Selection to zoom in. The colored part of the graph is the selected profile marker; clicking another marker shows how much that marker takes per frame, so its spikes are visible. So you choose which frames are included in the analysis.
The top ten markers are taken from the median frame. These are the ten markers that take the most time. Clicking one updates the Marker Summary - data for that one marker. It shows the top frames by cost, with buttons that jump to those frames in the Profiler. This is useful when looking for a pattern where the marker spikes across the range. A bar chart shows how the frames are spread by time for this marker; bars on the left are better, because they finish quickly. It also shows max, median, mean and min for this marker.
Right-click options - Zoom All to see all frames, Clear Selection, select the shortest frame, the median frame or the longest frame, Grow Selection and Shrink Selection, Select All. Select All includes the frames at the end where profiling was stopped. Those large frames skew the data, so it is better to select your own range without them.
Profiling inside the Editor combines the Editor with the game, which gives inflated values. For accurate data, profile a build, and for mobile, the mobile device itself.
The number of captured frames can be raised in Edit, Preferences, under Profiler.
Markers can be viewed as Total or Self. Total combines the marker with all the markers under it, which is why the player loop is often the largest. Self shows only the marker's own time. Self is useful to find the individual markers that really take the time.
By default only the main thread is analyzed, but more threads can be chosen, alone or as a group - for example the render thread together with the main thread. The Thread Summary gives the median time per thread and is a quick way to see whether a thread needs optimization.
Markers can be filtered. Typing a name in the name filter shows just that marker. Right-click a marker and choose Remove Marker to take one marker out of the analysis. To remove several, right-click and choose Add to Exclude Filter for each. This is useful to clean the data, for example to take the Editor markers out.
Markers happen at different depths in the Timeline. The depth slice option shows only the markers on one level - the top level has the player loop and the Editor loop; deeper levels give finer detail.
The marker columns can be changed with the Marker Columns dropdown, including a custom set.
Compare allows comparing two sets of data. With one capture loaded, the same data fills both slots, and with pair graph selection off, a different range can be selected in each - for example the tall spikes against a calm section. Then the differences show what causes the spikes. One set is blue and the other is orange. The Frame Summary shows the difference between the two. In the marker comparison the differences are bars from the center - to one side for the first set, to the other side for the second set. Reading the marker names with the biggest bars shows the area to focus on, for example rendering.
Data can be saved and loaded in both single and compare modes. This is useful for before and after an optimization, to make sure the change has a positive effect. Saved data can also be moved to another computer or shown in a meeting. The data in the Profile Analyzer can be lost when the Profiler window changes, so it is a good idea to save important data.
In compare mode with two different captures, pair graph selection is checked, so one drag selects the same range in both sets. Changing the analysis to Self and excluding the Editor markers gives a more accurate comparison.
Ideas for what to compare - a part of the game with many characters on screen against a calm part; moments where objects are spawned; the game after half a minute against after half an hour, to see system throttling, which matters a lot on mobile devices that heat up; different levels of the game; different hardware and operating systems, which also helps to define the minimum and recommended specifications.
STEPS
- Get data into the Profile Analyzer. 1) Install Profile Analyzer from the Package Manager. 2) Open Window, Analysis, Profile Analyzer and also the Profiler. 3) Record in the Profiler. 4) In the Profile Analyzer press Pull Data. 5) Drag over the frames you want, without the last frames where recording stopped.
- Find what is slow across many frames. 1) Select the range. 2) Look at the Frame Summary - median for the normal frame, max for the worst. 3) Switch markers from Total to Self. 4) Exclude the Editor markers. 5) Read the top markers. 6) Click a marker and jump to its worst frame in the Profiler.
- Compare before and after. 1) Capture and Save the first set. 2) Make the optimization. 3) Capture again in the same place of the game. 4) Open Compare and load the first set and the second set. 5) Keep pair graph selection on. 6) Read the marker comparison - the bars show which markers got faster and which got slower.
WATCH OUT
- Median is a better picture of the normal frame than mean, because a few big spikes pull the mean up.


MEMORY PROFILER (snapshots, resident and allocated memory, compare snapshots):
SUMMARY
- The Memory Profiler takes a snapshot of memory at one moment of the game and shows what uses the memory - textures, meshes, audio, scripts.
- Tools - Capture New Snapshot, Summary, Unity Objects, All Of Memory, Flatten Hierarchy, Compare Snapshots, import and export of snapshots.
LESSON
The Memory Profiler takes a snapshot of the memory usage at a specific point in the game and gives a detailed breakdown of how the memory is used. It can be used together with the Profiler and the Profile Analyzer. Before and after snapshots can be compared to see what effect an optimization had.
It is installed from the Package Manager, Unity Registry. If the right version is not in the list, use the plus icon and install it by name. It is opened from Window, Analysis, Memory Profiler.
With the game playing, click Capture New Snapshot. On first use there is a warning about sharing memory capture files outside the team, because a capture could contain sensitive data such as passwords. The snapshot then appears as a thumbnail in the snapshot list. Click the thumbnail to display the details.
The top diagram shows how memory is used. Resident memory is the actual memory used in the system RAM. There must be enough real space in RAM for the game to run. If the resident memory needed is larger than the RAM of the device, the game crashes. Allocated is the memory that was requested but is not yet filled - what Unity expects could be used. Not enough room for the allocated memory should not crash the game, but it is something to avoid by watching memory usage.
Other apps and the system also use RAM, so the lesson advises to keep memory use well below the physical memory of the device.
The Summary page gives a quick overview. There is a warning about snapshots taken in the Editor - the Editor memory is combined with the game memory, which gives an inflated value. For accurate results, take the snapshot from a build.
The allocated memory is split into categories. Clicking a category shows a description on the right. Memory sizes for graphics are estimated.
Managed memory is the memory related to C# code - the project scripts, the packages, and the parts of Unity written in C#. Native memory is used by the engine code. Managed memory consists of managed objects, empty heap space, and the memory needed for the scripting runtime. The garbage collector tracks which objects are still referenced and which can be collected, so their space is freed for new allocations. The managed heap grows when new objects do not fit in the free heap space.
There is also a quick overview of the top objects that take the most memory.
The Unity Objects section lists all game related objects that use memory. They are grouped into categories and ordered by the highest memory use. Many developers set a memory budget before production, so that the assets, textures and scripts fit into the target memory of the device. This view is useful to check that the categories stay inside the budget. A category can be opened to inspect each item. Clicking an item shows what references it and a breakdown of its size.
A tip to reduce memory - make sure Read/Write is disabled on assets that do not need to be changed at runtime.
With Flatten Hierarchy checked, all items are shown without categories and ordered by size, which makes it quick to find the largest items. The search bar finds a specific item.
The All Of Memory section shows all memory that Unity knows about - the game memory, the Unity memory, and other systems needed to run the game. Native and Managed both have a Reserved group, which is memory Unity keeps for its own processes.
For an accurate breakdown, build the game. In the build settings put the scene in the build and turn on Development Build and Autoconnect Profiler. Build and run. With the Memory Profiler open, it connects to the build. Click Capture to take a snapshot; click back in the game window so the capture can complete. The build uses much less memory than the same scene in Editor Play mode, which shows why a build is preferred.
A snapshot of a completely blank scene can be used as a baseline. Even a blank scene has some objects and uses some memory.
Compare Snapshots compares two snapshots. With the blank scene as snapshot A and the game scene as snapshot B, the comparison shows what the assets of the scene add to resident and allocated memory. It shows the differences by category, the managed heap, and the top Unity Objects categories. Colored bars show which snapshot is larger.
Clear memory numbers let you state the minimum and recommended RAM for the game.
Snapshots stay in the project until they are deleted. Right-click a snapshot to delete, rename or open its folder. The capture file can be copied to another project or computer and imported there.
Compare Snapshots is also used for before and after an optimization, to check that the change had a positive effect. Clicking an item shows the difference for that item.
STEPS
- Take an honest memory snapshot. 1) Open the build settings. 2) Turn on Development Build and Autoconnect Profiler. 3) Build and run. 4) Open Window, Analysis, Memory Profiler. 5) Play to the heavy place of the game. 6) Click Capture New Snapshot. 7) Click back in the game window so the capture finishes.
- Find what eats the memory. 1) Open the snapshot. 2) Read the Summary for the overall picture. 3) Open Unity Objects. 4) Check Flatten Hierarchy to sort everything by size. 5) Look at the top items - usually textures, then meshes and audio. 6) Click an item to see what references it. 7) Fix it in the import settings - smaller size, compression, Read/Write off.
- Check the result of a memory fix. 1) Keep the snapshot from before. 2) Make the change and build again. 3) Take a new snapshot in the same place of the game. 4) Select the first snapshot and click Compare Snapshots, then select the second. 5) Read the difference in Unity Objects.
WATCH OUT
- A snapshot can contain sensitive data from memory - do not share it outside the team.
- In Unity 6 these build options are in the Build Profiles window, opened from File, Build Profiles.


BAKED LIGHTING, LIGHT PROBES AND REFLECTION PROBES (lightmaps, bounced light):
SUMMARY
- Real time lights are expensive. Baking stores the light of static objects in textures, so it is not calculated every frame.
- Tools - light Mode set to Baked, static geometry, Lighting window, Progressive Lightmapper, Light Probe Group for moving objects, Reflection Probe for reflections.
LESSON
There are many ways to optimize, and each depends on the project, so after every change profile and test to confirm that performance really improved.
Manage the lighting. URP is built with optimized real time lighting in mind. In the forward renderer there is a limit of real time lights per object and per camera, and the limit is lower on mobile than on desktop. The pipeline asset also has per object light settings.
One of the best ways to improve performance is to bake the lighting whenever possible. Real time lighting can be expensive, and baking is a great way to gain performance back, especially if the lights in the scene do not move. Baking pre-renders the lighting of the scene into textures, which are then projected onto the geometry. This saves rendering time, because the lighting does not need to be calculated all the time. It is especially useful if the scene uses several lights.
Another reason to bake is bounced, or indirect, lighting. This is known as global illumination. It simulates rays of light that bounce around the environment and light up nearby objects. When baked, shadow areas receive the bounced light. It can be subtle, but it spreads the light more naturally and improves the look of the scene.
To bake, first mark the lights as Baked - select the lights and choose Baked in the Mode dropdown. Make sure the geometry of the scene is marked as static, so it is included in the lightmap calculation and contributes to the bounced light. Lightmap settings can also be changed per object on the Mesh Renderer; lower settings for distant or small objects improve baking time.
Then open the Lighting window from Window, Rendering, Lighting, create a new Lighting Settings asset, set up the lightmapping settings with the Progressive Lightmapper, and choose Generate Lighting.
Baking can take a long time. Start with a low lightmap resolution and size while iterating on the scene. Lighting data can be viewed in the Scene view with the draw mode dropdown. When the scene is finished, raise the resolution, size and samples step by step to what the target look needs. They should be no higher than needed, because lower resolution and smaller lightmaps lower the texture memory.
Use Light Probes. Light Probes sample the lighting of the scene during baking and pass the bounced light on to dynamic objects that move, such as characters or vehicles. This helps them blend into the baked lighting. To add them, choose Create, Light, Light Probe Group, then position the probes with the Edit Light Probes option. A probe can be duplicated to place more. Place probes where the lighting changes - close to shadow areas and where light colors change. Then bake the lighting again.
Use Reflection Probes. Reflection Probes project parts of the environment onto nearby geometry for more realistic reflections. By default Unity uses the skybox as the reflection; Reflection Probes make reflections match the surroundings. Choose Create, Light, Reflection Probe, position and size the probe where reflections are needed, and bake it in the Lighting window. Higher probe resolution gives better reflections for objects seen up close. For a camera that is far away, a lower resolution keeps the scene optimized, because less is stored in memory.
STEPS
- Bake the lights of a static scene. 1) Select the lights that do not move and set Mode to Baked. 2) Mark the environment objects as static. 3) Open Window, Rendering, Lighting. 4) Create a Lighting Settings asset. 5) Start with a low lightmap resolution. 6) Press Generate Lighting. 7) Raise the quality only at the end.
- Light a moving character in a baked scene. 1) Create, Light, Light Probe Group. 2) Press Edit Light Probes. 3) Place probes where the light changes - shadow edges, doorways, colored light. 4) Bake again.
- Better reflections. 1) Create, Light, Reflection Probe. 2) Place and size it around the area. 3) Bake it. 4) Keep the resolution low for things far from the camera.

URP CAMERA AND PIPELINE (occlusion culling, SRP Batcher, Frame Debugger):
SUMMARY
- Performance is also won by turning off what the camera and the pipeline do not need, by not drawing hidden objects, and by batching draw calls.
- Tools - camera options (post processing, shadows, Depth Texture), Occlusion Culling, URP Asset per quality level, SRP Batcher, Frame Debugger, Profiler.
LESSON
Manage the camera settings. URP has ways to optimize a camera by turning off render processes that are not wanted. This is very useful when the project targets both high end and low end devices. Turning off things like post processing, shadow rendering or the depth texture removes expensive work on lower quality settings and raises performance.
Another way to optimize the camera is occlusion culling. By default the camera draws everything inside its view frustum, including geometry hidden behind walls or other objects. Drawing geometry is expensive, and there is no point in drawing objects the player cannot see. With baked occlusion data Unity ignores the parts of the scene that are blocked from the view of the camera, which reduces the geometry drawn per frame. To use it, mark the geometry as occluder static or occludee static, open Window, Rendering, Occlusion Culling, and click Bake. It can be previewed in the Scene view with the Visualization tab.
Manage the render pipeline settings. URP is designed for many target platforms and devices, so the URP Asset has many settings that control performance. The asset is selected in the Project window, or found in Edit, Project Settings, Quality. Each quality level in the project can hold a different URP Asset, so different assets can be made to control how the game performs at each quality level.
Many of these settings change both performance and the look of the scene, so it is worth experimenting. In general, to gain performance, reduce shadow resolution and shadow distance as much as possible, and turn off features the project does not use, such as the depth texture or the opaque texture.
Enabling the SRP Batcher turns on the batching method of URP. The SRP Batcher automatically batches together meshes that use a compatible shader. With many dynamic objects in the scene this is a useful way to gain performance.
Use the Frame Debugger. For a better understanding of what happens during rendering, use the Frame Debugger and the Profiler. The Frame Debugger gives a breakdown of all the draw calls the game makes before the final image. It is a great way to see why some frames take longer to draw, or why the draw call count of the scene is high. It is opened from Window, Analysis, Frame Debugger. With the game playing, press Enable to see the scene at each point of the rendering. It also shows the renderer features that are active in the pipeline and what they add to the rendering.
Use the Profiler. The Profiler shows how long the project takes to complete a frame, with an overview of rendering, memory and scripting. It helps to find scripts that take a long time and points at bottlenecks in the code. In the Hierarchy mode it gives a breakdown of the time of a single frame and each call made in it.
STEPS
- Cheaper settings for weak devices. 1) Open Edit, Project Settings, Quality. 2) Make a separate URP Asset for the low quality level. 3) In it lower shadow resolution and shadow distance. 4) Turn off Depth Texture and Opaque Texture if no shader needs them. 5) Turn off post processing on the camera for that level. 6) Profile on the device to confirm.
- See why there are many draw calls. 1) Open Window, Analysis, Frame Debugger. 2) Enter Play mode and press Enable. 3) Step through the list on the left. 4) Look for objects that are drawn one by one instead of in a batch. 5) Read the reason the batch was broken. 6) Fix it - same material, same atlas, same shader.
- Do not draw hidden objects in a 3D scene. 1) Mark walls and big objects as occluder static. 2) Mark smaller objects as occludee static. 3) Open Window, Rendering, Occlusion Culling. 4) Click Bake. 5) Check the result in the Visualization tab.
WATCH OUT
- The Frame Debugger shows draw calls, not time. For time use the Profiler.
